# 会计约束与实现边界

完整强制规则见 AGENTS.md；这里保留容易踩坑的实现事实。

- 信用卡三块：消费返利、perk 减年费/成本、已到账 SUB 减手续费/诱导消费/替代损失。Checking / savings churn 单列。主总额用 reports.report，不能拿仍含兑换价值的 core.summary.net 代替。
- 必付学费本金不是损失；2.52% 刷卡手续费可归 SUB，正常赚点归消费返利。测算不发记账事件。
- UR 与 Aeroplan 默认各 1.8¢，保留滑块/即时重算；不展示当前 UR 余额，不追踪 SUB 已消费额，旧字段留作导入兼容。目标、期限、到账状态保留。
- 余额快照无收入。earn.affectsBalance:false 只记来源/估值，不改变余额；适用于补记已含于快照的来源，也适用于 transfer.received 已含 bonus 后独立记 bonus 收入。同年仅年份来源与快照排序未知时隐藏该计划余额，不假设先后。
- 转点本金无收入；兑换价值、剩余资产与赚点估值分别显示，不叠加。飞行里程非信用卡消费返利。
- USD 税费未知（null/缺省）或现金参考价未知时不算实测 CPP；已确认零税费可用 0。保留原币金额及币种，不自动汇率换算。
- 实际 SUB earn/cashback 已记录时不再叠卡片现金摘要；未知摘要到账年份不推算开卡年份。混合或部分到账需逐笔真实事件，不推算缺口。
- 参考起价、次数和个人实际价值分离。Status 与卡片重叠只录同次使用一次并写归因；当前无独立 Status 账本/自动去重。
- Category 已按倍率/现金百分比/有效日期比较，上限仍是备注和人工维护；不得宣称自动计算剩余额度。银行未知开户日、更多 SUB 档位、扩展字段校验、买点/非卡成本口径仍在 BACKLOG。
- 具体日期、金额、周期未知时不编造。周年无锚点不推 Jan 1；结单周年与简单日历周年不同，按指定真实周期或待核对处理。
- 兼容旧 `includedInSnapshot` 的有效同计划快照 ID（以及布尔 true）；若未明确设置 `affectsBalance`，不再次增余额。新增共享 `core.earnAffectsBalance` 供余额和编辑默认值使用，原关联字段保留；回归只使用虚构快照/点数。
- 兑换可另外保留原币现金参考价、汇率日期/来源、舱位、持卡折扣与估计折扣前点数。USD 参考价和税费供现有 CPP 使用；用户提供的近似汇率要注明来源，折扣比较不另记收入，也不增加扣点事件。出行日不能冒充订票日。
- 用户同时提供 transaction date 和 posted date 时，费用报表的 `date` 使用 posted date，另存 `transactionDate` / `postedDate`；不从今年实付日期猜下次年费日。未知到账日可保留已确认到账状态和原周期，不补假日期。
- 从准确开户日起计算一年期优惠时，分别保存周年/end-exclusive 边界和模型最后适用日，标注这是推算、银行入账边界未核对。用户关注优惠截止，不要求跟踪当前优惠消费/上限余额；未知上限仍保留未知。
- 用户指定起价作为服务参考时只更新参考字段，不将次数自动相乘、不自动填个人实际价值；Status/卡片重叠保留单条使用与来源备注。官方报价的票种、出票日期适用条件和税前口径要保留。
- 用户明确负年费只依据已确认使用/到账的权益认可价值减实付年费及相关成本；排除消费返利、SUB、全部额外积分奖励、未用额度、估计和参考价。零净额为刚好覆盖，大于零才超过；实付成本缺失不认证覆盖。`cardBenefits` 独立于总收益计算。
- 总览 `benefitNet` / `extraPoints` 分列，原 `report.perks` 兼容保留合计。积分奖励仍计入原归因卡总收益，不能称为现金报销。`sources` 与原记录 ID/备注和公式让每项可核对。
- 重叠服务必须明确已认可 `actualValue` 及本卡归属价值 `cardAttributionValue` 才计年费覆盖，后者不超过前者；`valueStatus` 可在表单确认，reference-only/estimated/unvalued 不认证。未自动去重不同使用 ID。
- `pointPrograms` 按 Currency 显示当前余额、CPP 资产假设、逐笔兑换和历史加权 CPP；加权用净价值/已定价净点数，不平均每笔比例，退款冲回，未知价税不进分母。资产与历史情景不加收入。用户再次确认 UR 暂不追踪，约零不生成零快照。
- 年费覆盖当前按报表年份/全部年份，不是自动年费周期；权益剩余额度按当前各项周期，标题与口径必须明确。后续周期筛选列入 BACKLOG。
- 服务价值录入先区分“每次价值”和“所有使用合计”：`actualValue` 是该条记录合计认可价值，`quantity` 独立计次，计算时不能再乘次数。用户确认合计后更新已有记录与确认状态，不新增重复使用；个人认可合计不会自动指定 Status 重叠权益的本卡归属价值。
- 用户后来明确将重叠服务归属卡片时，允许将已确认合计填入 `cardAttributionValue`，同次服务只算一次；这是用户认可的分配，不要求证明没有 Status 时的反事实增量。参考价仍独立，未知个人价值须先确认。
- 有可靠余额快照却因同年未知日来源而隐藏余额时，先核对已有来源备注/快照，给确实已含于余额的来源补 `includedInSnapshot` / `affectsBalance:false`。不得绕过所有年份歧义检查，不猜到账日、不改余额来凑数；赚点收入保持原分类。
- `reports.sortedCards` 用视图副本统一总览、信用卡、权益及卡片选择器顺序：计划年费倒序、同费开户倒序。未知费末尾，未知日用月份精度，同月月份记录放在确切日期之后；产品事件不改变开户排序。
